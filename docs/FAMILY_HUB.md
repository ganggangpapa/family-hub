# 가족 연결 계획 (우리집 허브)

> 이 문서와 `supabase/schema.sql`은 세 앱이 같이 쓰는 공용 설계입니다. 저장소: `ganggangpapa/family-hub`

> 상태: **1단계(오늘저녁) 시험 준비** · 작성 2026-11-20 (부모가 Supabase 프로젝트를 만들어 승인)
> 하루노트, 오늘저녁뭐먹지, 눈을뜨자를 "가족끼리 주고받는" 모델로 바꾸는 계획입니다.
> 서버와 로그인이 들어가므로 CLAUDE.md의 '멈춤 조건'에 해당합니다. 부모가 이 문서를 승인한 뒤에 단계별로 진행합니다.

## 1. 방향 (결정된 것)

- **처음에는 우리 가족 전용으로 테스트합니다.**
- **지인이 원하면 가족을 추가할 수 있게** 처음부터 "가족 단위로 나뉜 구조"로 만듭니다.
  나중에 다시 만들지 않고, 초대 코드만 주면 다른 가족이 들어올 수 있게 합니다.
- 카톡과 경쟁하는 채팅은 만들지 않습니다. **앱을 써야 생기는 대화**에만 집중합니다.
  (문제 결과 → 칭찬, 저녁 메뉴 → 투표·요청)

## 2. 전체 그림

```
            [우리집 홈]  가족 로그인 · 오늘의 카드 · 알림
             /          |            \
      하루노트       눈을뜨자       오늘저녁뭐먹지
     (초등 학습)    (중등 학습)    (메뉴 추천·투표)
             \          |            /
          [공용 서버: Supabase 한 개 프로젝트]
          가족 · 구성원 · 학습 요약 · 메시지 · 투표
```

- 세 앱은 **저장소를 합치지 않고** 따로 둡니다. 로그인과 데이터베이스만 같이 씁니다.
  (주말에만 작업하므로, 앱 하나가 고장 나도 나머지는 그대로 돌아가게)
- 우리집 홈은 `apps/family-chat`의 **가족 홈** 화면으로 만듭니다 (2026-11-20 결정). 메뉴: 오늘저녁 · 초등학습 · 중등학습 · 가족채팅. 자세한 것은 `docs/family-chat-spec.md`.

## 3. 핵심 설계 원칙

| 원칙 | 내용 | 까닭 |
| --- | --- | --- |
| 기기 저장이 먼저 | 지금처럼 localStorage에 먼저 저장하고, 가족 연결을 켠 경우에만 서버로 보냄 | 연결 안 해도 앱이 그대로 동작, 인터넷 끊겨도 풀 수 있음 |
| 요약만 보냄 | 문제 하나하나가 아니라 "날짜·과목·푼 수·맞힌 수·연습할 단원"만 | 개인정보 최소화, 무료 용량 절약 |
| 아이는 이메일 없음 | 부모만 이메일(또는 구글)로 로그인. 아이 폰은 부모가 만든 **6자리 연결 코드**로 가족에 붙음 | 아이 개인정보를 받지 않음 |
| 아이 정보는 별명·학년만 | 실명, 학교명, 생년월일은 서버에 올리지 않음 | 확장할 때 법적 부담을 줄임 |
| 가족끼리만 보임 | 모든 데이터에 `family_id`를 붙이고, 서버 규칙(RLS)으로 자기 가족 것만 읽고 쓰게 | 지인 가족이 늘어도 서로 못 봄 |
| 앱마다 맞는 방식 | 하루노트는 `<script>`로 불러옴(빌드 없음 유지), 오늘저녁은 npm 도구 사용 | 각 앱의 기술 원칙 유지 |

## 4. 데이터 구조 (처음 버전)

| 표 | 들어가는 것 |
| --- | --- |
| `families` | 가족 이름, 초대 코드 |
| `members` | 가족 id, 역할(부모/아이), 별명, 학년, 로그인 계정(부모만) |
| `link_codes` | 아이 기기 연결 코드, 만료 시간 (함수로만 사용) |
| `study_daily` | 아이, 앱(하루노트/눈을뜨자), 날짜, 과목, 푼 수, 맞힌 수, 연습할 단원 |
| `messages` | 보낸 사람, 받는 사람, 종류(응원/칭찬 스티커/보여 주기/먹고 싶어요), 내용, 읽음 |
| `meal_polls` | (오늘저녁) 날짜, 메뉴 후보 2~5개, 올린 부모, 마감 시각 |
| `meal_votes` | (오늘저녁) 투표, 누가 몇 번 메뉴를 골랐는지 (한 사람 한 표) |

## 7. 미리 알아 둘 점

- **무료 플랜 한계**: Supabase 무료 프로젝트는 한동안 아무도 쓰지 않으면 잠들 수 있습니다(대시보드에서 다시 깨움). 가족이 매일 쓰면 문제없지만 방학 때는 확인 필요.
- **각 앱의 기술 원칙이 바뀝니다**: 앱을 연결하는 단계에서 그 앱 CLAUDE.md의 "서버 없음"·"로그인 안 함"을 "가족 연결을 켠 경우에만 필요한 것만 서버로"로 고칩니다.
- **범위 관리**: 1단계(저녁 투표)가 가족 안에서 2주 이상 실제로 쓰이는지 본 뒤 2단계로 넘어갑니다. 안 쓰이면 거기서 멈추고 고칩니다.
